# issue スキル

Claude が作業中に人間の判断・権限・レビューが必要な事項に遭遇した際、`ISSUE.md` に相談を書き出して作業をブロックせず進めるためのスキルです。

## 基本方針（自動発動）

以下のような場面では、ユーザーに指示されなくても自発的にこのスキルを使う:

- 判断に権限が必要（本番デプロイ、破壊的操作、外部サービスへの投稿など）で自分では決められない
- 社内システムやアクセス権が必要で、Claude では確認できない
- 仕様・設計方針が複数あり選べず、ユーザーの意図が不明
- 他の作業のブロッカーになっているが、今すぐ解決できない

このような事項に遭遇したら:

1. 該当の相談を `ISSUE.md` に追記する（フォーマットは後述）
2. その場で回答を待たずブロックしない — 書いたらすぐに他の作業（TODO 等）に進む
3. 作業の区切りやセッション終了時に、追記した相談があればユーザーに一言触れる

---

## フォーマット

```markdown
## [ ] 相談タイトル
起票日: YYYY-MM-DD

**背景**: なぜこの相談が必要か
**相談したいこと**: 人間に決めて/やってほしいこと
**影響**: 未解決だとブロックされるTODO
**回答**
**判断**
```

- `[ ]` → `[x]` への変更は **必ず Claude 自身が行う**。人間はチェックボックスを操作しない
- **回答**欄: 人間が記入する場所。Claude は追加時に空欄のままにしておく
- **判断**欄: 人間の回答を Claude が読んで、その回答をどう解釈し・どう対応したか（または対応しなかった理由）を Claude が記入する場所
- チェックボックスの状態:
  - `[ ]` かつ **回答**が空欄: 未回答（人間の対応待ち）
  - `[ ]` かつ **回答**が記入済み: 回答はあるが Claude が未処理（`/issue check` の対象）
  - `[x]`: Claude が回答を確認し、**判断**を記入した上でチェック済み

## /issue add [相談内容]: 相談の追加

1. ユーザーからの相談内容を受け取る（省略時は状況から背景・相談したいこと・影響を自動で整理する）
2. `Bash(date "+%Y-%m-%d")` で起票日を確認
3. `ISSUE.md` が無ければ初期化する（後述の /issue init）
4. 上記フォーマットで `ISSUE.md` の末尾に追記する（**回答**・**判断**は空欄のまま、チェックは `[ ]`）
5. 追記した旨をユーザーに一言報告し、回答を待たず他の作業に進む

---

## /issue list: 相談一覧の表示

1. `ISSUE.md` を読み込む
2. 次の3状態に分けて一覧表示する
   - 未回答（`[ ]` かつ **回答**が空欄）
   - 回答あり・未処理（`[ ]` かつ **回答**が記入済み） — `/issue check` の対象として目立たせる
   - 処理済み（`[x]`）
3. 未回答・未処理の相談は特に目立たせる

---

## /issue check: 回答の確認と判断

1. `ISSUE.md` を読み込む
2. `[ ]` のまま **回答**が記入されている相談を探す（Claude がまだ処理していないもの）
3. それぞれの相談について:
   1. 回答内容を読み、どう解釈し、どう対応するかを判断する
   2. その判断内容（対応する/しない、どう対応したか、理由）を **判断** 欄に記入する
   3. 判断に基づき、影響を受けていた TODO・作業があれば再開・実行する
   4. チェックボックスを `[ ]` から `[x]` に変更する（**この変更は Claude が行う。人間には変更させない**）
4. 処理した相談があれば、その内容と対応結果をユーザーに報告する
5. 対象の相談が無ければ、その旨を報告する

## /issue init: ISSUE.md の初期化

`ISSUE.md` が存在しない場合、以下のテンプレートで新規作成する。既に存在する場合は上書きせず、その旨を伝える。

```markdown
@CLAUDE ISSUE List

## [ ] 相談タイトル
起票日: YYYY-MM-DD

**背景**:
**相談したいこと**:
**影響**:
**回答**
**判断**
```

作成後、`.gitignore` に `ISSUE.md` を追加するかどうかを必ずユーザーに確認する（自動判断で追加/スキップしない）。「追加する」と回答された場合のみ、`.gitignore` の末尾に `ISSUE.md` を追記する。既に `.gitignore` に含まれている場合は追加せず、その旨を伝える。

---

## 相談記録のルール

- **タイトルは具体的に**: 一覧で見て何の相談か分かるようにする
- **背景・相談したいこと・影響は必ず埋める**: 追加時は **回答**・**判断** の2欄だけ空欄にする
- 一つの相談につき一つのブロックとして追記する（複数の相談を一つのブロックにまとめない）
- 同じ内容の相談が既にある場合は、新規追加せず既存の相談に追記コメントする形で対応してもよい
- `ISSUE.md` は人間がレビューする前提のため、断定的な言い方より「〇〇か◯◯かで悩んでいる」のように選択肢を示す書き方が望ましい
- **チェックボックスは Claude だけが操作する**: 人間が回答を書いても `[ ]` のままにしておき、Claude が **判断** を記入してから `[x]` にする

---

## まとめ

- `/issue init` : ISSUE.md を新規作成して初期化する（ファイルが無い場合）。作成後 `.gitignore` への追加を必ずユーザーに確認する
- `/issue add [相談内容]` : 相談を新規追加してブロックせず作業を続ける
- `/issue list` : ISSUE.md の相談一覧（未回答/回答あり未処理/処理済み）を表示する
- `/issue check` : 回答が記入された相談を読み、**判断** を記入し、Claude 自身が `[x]` にして対応を再開する
- 判断に迷ったり権限が必要な場面に遭遇したら、指示されなくても自発的にこのスキルを使い、ISSUE.md に書いてから作業を続ける
- チェックボックスの `[ ]` → `[x]` は常に Claude が行う。人間は **回答** 欄に記入するだけでよい
